日期：2026-09-05。已完成可执行夹具、旧脚本实跑和两档模型各六个独立行为样本。旧技能固定为 v0.5.0 / `63e05233e149ec7ce5170bc0fe64df1870b10e6f`，技能规则及安装目录未修改。

**本轮最直接的改造依据：将完工联动和机器证据保护交给工具，保留模型判断；不能只靠更强模型或更多规则解决闭环。** 当前单样本下 Astra 在停止、证据复用和文档收口上更完整；Luna 也正确完成了函数修复和缺失前端识别。样本不足以裁定生产模型或统计可靠率。

## 2. 六场景对照

下表为主 Agent 核对源文件、工具轨迹与自述后的判断，不是受测 Agent 自评，也不是人类 UX 试用。避免将不同维度压成一个成功率。

| 场景 | Astra | Luna |
|---|---|---|
| B01 无目标 | 无测试、无写入，正确结束 | 返回 no_action，但仍启动 1 次测试并生成证据 |
| B02 正常完工 | 函数实测通过；卡、日志、交接齐全 | 函数通过；声明已收口但缺开发日志 |
| B03 中断恢复 | 恢复交接，保留原日志；另跑 1 次测试 | 恢复交接，追加恢复事件；另跑 2 次测试。没有重复原始完工事件 |
| B04 有效证据复用 | 引用既有回执，未重跑 | 重跑 1 次；手抄回执后附加字面量 `\\n`，JSON 无法解析；缺日志 |
| B05 旧证据失效 | 先失败、修复、再通过；收口记录齐全 | 同样先失败、修复、再通过；交接仍待验收且无日志，却声明完成 |
| B06 后端通过、页面缺入口 | 明确用户功能不可交付，卡与交接记录原因 | 同样识别缺入口，返回 incomplete；审计结论留在自述，卡未回写 |

两档都没有把 B06 的后端通过误判为用户功能通过。这说明不能仅凭原规则漏洞推定 Agent 必然误报；后续需增加更隐蔽的真实浏览器场景，才能评估界面接线和 UX 能力。

B03 的追加恢复事件有实际新事实，不应为了“一日只一行”删除。Astra B06 的 `task_status=completed` 明确指审计完成，正文和卡都否定功能完成；不能只搜索 completed 字样判伪完成。

## 4. 旧脚本的独立事实

1. `check_card.py` 对存在的方向引用和不存在的 `docs/missing.md#absent` 均返回 0。它目前检查字段文字，不检查引用存在性；不是方向链已验证的证据。
2. `collect_evidence.py` 正确记下内部命令退出码 7，但采集器返回 0。必须区分采集成功与验收通过，不能仅看最外层退出码放行。

这是实际执行结果，不依赖模型评价；原输入、输出和机器报告见旧脚本回执。

## 5. 由本轮证据限定的改造顺序

1. **完工入口负责必需回写。** 卡、日报、交接的更新与校验由一次操作承接；不让模型分别记住每个文件。B02/B05 已显示“代码正确但收口遗漏”。
2. **机器回执单独拥有写权限。** 测试工具写不可变验证 ID 的原始结果，Agent 只能引用或另写解释；避免抄写浪费、JSON 损坏，以及 current.json 覆盖历史失败。原始结果、采集状态和验收状态分开。
3. **停止/复用检查放进受管执行入口。** B01/B04 中无目标或无变化仍启动测试；B03 中恢复记录又重复实测。判断未知影响仍允许必要复验，不能为省调用漏测 B05。
4. **统一技能资源定位。** Luna 的 10 次错误来自未带 skill/ 的路径请求；产品入口应返回可直接使用的资源定位，减少宿主相对路径歧义。
5. **继续按用户路径验收前端。** 两档在明显缺入口时判断正确，但尚未测真实浏览器交互、持久化和视觉状态；不能据此宣称前端问题已解决。

首轮不据此增加更多治理角色、自动派工或规则篇幅，也不直接固定“轻量模型只做某类任务”。先修确定性闭环，再以相同场景及未见变体比较改造前后。

- 脚本首轮正向控制未建立方向源，已补为 scripts-r2；旧记录保留为排查资料。
- Codex CLI 启动探测失败，Claude Code OAuth 过期，已有 API 入口超时；这些只记环境失败，不记旧技能或模型失败。未更改账户、重新登录或安装 CLI。
