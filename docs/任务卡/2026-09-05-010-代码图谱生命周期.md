# 010 · 代码图谱生命周期

- 目标：以固定 0.8.1 运行时提供项目内索引、状态和低 token 查询适配层。
- 写域：`scripts/donghe_graph.py`、`tests/test_graph.py`、本卡。
- 不变量：索引只写 `.donghe/codegraph`；不安装、不更新、不联网、不改宿主配置；新代成功后才原子切换；陈旧图谱不得冒充当前图谱。
- 生命周期：`refresh(project)` 在变化时全量建独立 generation、未变化时复用；`status(project)` 以源码字节和路径指纹判定 current/stale/missing/unsupported；`search(project, query)` 只在 current 时查询图谱，否则返回有界逐行精确搜索并显式标记 fallback；`trace(project, function_name, direction, depth)` 提供深度不超过 5 的有界调用链。
- 隔离：每代独立 `CBM_CACHE_DIR` 与 `XDG_CONFIG_HOME`，写入固定空扩展配置并记录配置指纹，关闭跨仓 LSP；上游 macOS/POSIX 路径实现读取 `XDG_CONFIG_HOME`；工作树之间没有共享索引。
- 源范围：明确源码扩展白名单（含病例库所需 Dart）并排除秘密文件、上游项目配置、`.git`、`.donghe`、`docs/东合`、依赖与构建产物；覆盖口径为 `policy-selected`，不声称任意语言完整；指纹和上游索引共用受管快照文件集；未提交内容和删除均进入指纹；纳入范围的符号链接拒绝；超单文件、总字节或文件数预算时拒绝宣称覆盖。
- 运行时：正式默认路径只接受版本精确等于 0.8.1 且 SHA-256 命中同目录 `manifest.json` 的二进制；显式 binary 参数只用于测试。
- 数据库健康：generation 元数据固定记录每个 DB 的相对路径、字节数和 SHA-256；读取时要求清单集合完全一致、SQLite `quick_check` 通过，并核对 `projects.name/root_path` 绑定当前 generation 快照。多余、缺失、损坏、错项目或旧元数据均判 stale，查询转有界 fallback；损坏代保留作诊断证据，刷新另建新代。
- WAL 稳定化：上游数据库使用 WAL 模式；索引子进程退出后先执行有界 `wal_checkpoint(TRUNCATE)`，再计算主库清单摘要与项目绑定，避免 full-suite 中主库/WAL 过渡状态造成偶发误判。checkpoint 锁或损坏仍失败，不自动重试或放宽校验。
- 查询内生写入：上游每次打开 store 都会设置 WAL、创建缺失索引并可能执行 SQLite optimize。成功查询后适配器再次 checkpoint，仅在 DB 文件集合不变、源码指纹未漂移、schema/quick_check/project binding 全部通过且 current generation 未切换时，原子更新该代 inventory；DB 哈希门禁仍保留。隔离样本查询前后主库 SHA 未变化，但 full-suite 已实测出现内生变化，查询后的 refresh 现必须复用同代。
- 上游排除：受管快照先去除上游无条件忽略的依赖、缓存和配置文件，再使用 `full` 模式；正常的 tests/docs/scripts 不因 fast 模式被静默丢弃。元数据仍只声明 `upstream-supported-within-policy`，并保留上游 excluded 响应；同源码、同构建策略的失败默认不会盲目重跑。修复环境后可显式调用 `refresh(..., retry=True)` 重试一次；retry 只绕过失败标记，不绕过源码、运行时、快照或数据库校验。
- 真仓证据（2026-09-05）：Forms 新克隆单次建代为 966 files / 10,554 nodes / 29,532 edges，图谱命中 `GFFormDisplay` 且源码位置回读 1；medical 新克隆单次建代为 888 files / 12,868 nodes / 27,617 edges，命中 `MetricExtractionCandidate` 且源码位置回读 1；两仓第二次 refresh 均复用同 generation。
- 验收：小型 Python 两函数仓真实索引并搜索调用；修改后陈旧、刷新后恢复；复制工作树独立；失败保留旧 current 与诊断；宿主 HOME 无写入。
- 证据命令：`python -m unittest tests.test_graph -v`
