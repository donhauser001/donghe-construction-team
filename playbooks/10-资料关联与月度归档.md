# 10 · 资料关联与月度归档（v0.7.0）

仅在项目明确采用 CLI 资料管理且任务涉及治理资料或归档时读。已有正本只链接，不因决策查询自动 adopt/record 或复制正文。资料必须来自明确事实，不从目录名称猜进展，不建九套空模板。

## 资料与身份

固定根 `docs/东合/资料/<kind>/<id>.md`；kind 为 idea / blueprint / roadmap / next / debt / knowledge。
任务、开发日志、当前交接沿用 playbook09 路径。身份固定，标题可变。已有外部资料保留原位置并在正文引用；不自动搬入或声称已完成历史迁移。

在技能目录执行，spec 文件只是输入请求，不是第二份正本：

```sh
bin/donghe --project <项目> record --spec <资料.json>
bin/donghe --project <项目> record --update --spec <更新.json>
bin/donghe --project <项目> link B001 I001 --relation derived_from
bin/donghe --project <项目> link B001 task:T001 --relation implements
bin/donghe --project <项目> catalog
```

资料请求示例：`{"id":"I001","kind":"idea","title":"一项未承诺的想法","body":"用户原意及来源","state":"open"}`。
机器元标签放在源文档唯一的 donghe-meta JSON fenced block 中；正文保留理由和上下文。
state 仅为 open / active / closed 的声明，不表示已验证。历史createdAt/updatedAt须有事实来源且含时区；未提供则用真实当前时间。
update保留id/kind/createdAt/已有feedback，updatedAt由工具更新。归档资料先恢复再修改。

关系仅使用 derived_from（源自）、implements（落实）、relates_to（相关）、supersedes（替代）。
任务目标写 `task:T001`，资料目标直接写ID。未知目标、重复身份、替代循环与坏元标签有诊断，不静默推断修复。

finish后沿“落实任务的资料 → derived_from上游”回写幂等反馈；relates_to不会推导因果。
反馈记录本次任务事件、证据与来源链，不自动采纳想法、兑现整个蓝图或清偿全部技术债。
完工事务已完成而资料反馈失败时，CLI报错，catalog暴露missing_feedback；解决冲突/恢复归档源后重试finish，不重跑业务验证来修文档。

## 月度政策

每个自然月首次 init 或 finish 检查一次，记录于 `.donghe/state/maintenance.json`；已有待恢复完工事务则跳过归档。
坏资料或归档异常记录为maintenance blocked，当月不反复重试；不把成功完工报成失败。修复后用显式archive重试，显式写入仍严格拒绝坏计划。
不启动后台计时器。项目闲置期间不触发；再次开工时补处理此前符合条件的月份。
只有早于本月的 closed资料、正本已completed任务及其专属回执、旧日日志可归档。
当前月份、active任务/资料、当前交接与共享指纹不移动。共享指纹不做垃圾回收。
同月主动需要维护时：

```sh
bin/donghe --project <项目> archive
bin/donghe --project <项目> archive --month 2026-08 --apply
bin/donghe --project <项目> archive --month 2026-08 --restore
```

不带apply是只读预览；status、catalog、网页刷新都不触发归档。手动月份必须早于当前月。
物理档案镜像原逻辑路径：`docs/东合/档案/YYYY-MM/docs/东合/...`；原ID与原文引用不改。
源与档案由确定性扫描统一读取，清缓存后仍能追溯，不依赖模型总结或常驻索引服务。

移动前记录路径和SHA-256，逐文件移动，操作日志在 `.donghe/state/archive/`。中断后重试同一操作恢复；不是文件系统级全批原子事务。
归档或恢复发现同名、源已变、坏日志、重复物理副本、越界或符号链接时停止，不覆盖。
恢复缺少原归档日志时只验证运输字节，结果明确标为transport-only；原回执仍独立校验，不冒充历史认证。
归档是存放方式，不能把过期证据变成通过，也不能生成新施工授权。归档任务先restore，再在明确授权下verify重开。

## 限制

当前按单写者运行；不要在另一验证/编辑过程仍运行时并发归档。历史来源不明的资料留在原位。
本版是文件级身份和显式关系；章节级事件标签、复杂搜索分页、跨机器并发、无事实源的历史不补；有据接入与代码图谱见playbook11。
默认状态只返回归档数量和问题；完整移动清单仅在显式archive预览中输出。catalog默认50项且支持类型、文字、offset分页；原文按需读。
