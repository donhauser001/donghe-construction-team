# 09 · 最小完工闭环（v0.7.0）

目标：一次授权任务产生可追溯证据、日记与交接，并在东合项目进化史可见。
本路径取代旧卡目录与手工回写流程，不要求同时维护两套状态。

## 接入与产物

先读项目 AGENTS.md 指向的当前事实；只调查本任务相关范围。
新项目记录用户目标即可；旧项目保留已有资料，不批量迁移或虚构历史。
确认 Git 检查点；有未提交工作就新建 worktree。本工具不替用户提交或推送。

在技能目录执行（`<根>` 为项目绝对路径）：

```sh
python3 scripts/donghe.py --project <根> init
python3 scripts/donghe.py --project <根> task --spec <验收契约.json>
python3 scripts/donghe.py --project <根> status
```

统一产物：`docs/东合/任务卡/`、`docs/东合/证据/`、`docs/东合/开发日志/`、`docs/东合/工作交接.md`。
恢复日志在 `.donghe/state/operations/`。不预建蓝图、未来池、知识库等空文档。
任务卡中结构化契约是正本；输入 JSON 只是导入请求，不维护第二份可编辑状态。

## 最小验收契约

```json
{
  "id": "T001",
  "title": "落实一项用户已授权的改动",
  "authorization": "用户要求及对应的项目方向来源",
  "criteria": [{
    "id": "unit", "label": "相关行为验证",
    "command": ["python3", "test_feature.py"],
    "inputs": ["src", "test_feature.py"], "reuse": true
  }],
  "issues": []
}
```

验收在开工时定义，必须覆盖实际行为；禁止事后删除失败项来过闸。
`inputs` 必须覆盖受测源、测试文件、配置和依赖锁，不仅写一个入口文件。
远程服务、浏览器在线状态或无法完整指纹化的环境使用 `reuse: false`。
有 UI 变化必须单独注册真实浏览器验收；API 通过不证明用户界面可用。
`authorization` 是来源记录，不是机器能证明的用户授权；agent 仍须核对上下文。

## 验证与完工

```sh
python3 scripts/donghe.py --project <根> verify T001 unit
python3 scripts/donghe.py --project <根> finish T001
python3 scripts/donghe.py --project <根> next
python3 scripts/donghe.py --project <根> serve --port 4318
```

验证运行契约中的 argv，不接受手填“成功”。失败输出照常保存。
同范围、同契约、同环境的有效回执可复用；源变化或回执损坏阻止验收。
排查失败优先运行 `receipt <项目内回执路径>`，读取有界摘要；需要细查时再打开原始输出。
`receipt` 命令退出 0 只代表读取完整性有效；当次验证是否失败须看摘要的 exitCode、error 和 inputChanged。
仅通过 CLI 引用证据，不编辑机器回执；只读权限与摘要是误改检测，不是同一 OS 用户的安全隔离。
`finish` 统一回写任务卡、当日日志和当前交接；中断后再次执行同一命令恢复。
它是可恢复的多文件事务，不是文件系统级原子提交；发现并发修改保留冲突，不覆盖用户内容。
若中断后输入改变，使用 `abort T001` 按快照撤销该未完成事务，再验证；有人改过回写文件则保留冲突，不强行回滚。
已完工任务的输入漂移后可重新 verify / finish，旧回执保留，新一轮完工单独记入日记。
`next` 返回 stop 就停止，不为了跑满时间再测一次。调度边界见 `references/unattended.md`。

## 指纹与阅读预算

新回执保存前后指纹引用，相同清单仅存一份于 `docs/东合/证据/指纹/`。
回执和引用对象都必须通过摘要校验；共享对象损坏会使所有引用它的验收失效。
旧版内嵌指纹回执按原样读取，不在浏览时批量迁移。
默认摘要只返回命令、退出码、输入计数和有界stdout/stderr节选；完整清单与输出按需读取。
历史回执表示当次命令结果，不自动代表当前代码仍可通过。
共享指纹不能随单份回执删除；本版不提供自动清理、归档或迁移操作。

## 阅读、回滚与限制

界面只读本项目当前资料，按任务历程与验收状态呈现；按钮打开原文与回执。
原始凭据损坏或代码变更后，界面不能继续把旧验收显示为当前通过。
隔离 worktree 的代码用独立提交回滚；保留证据和事务资料用于追溯。
v0.6.0程序不认识新版引用格式；回滚试点源码不会自动转换已产生的新回执，保持试点数据隔离。
不直接删工作区或重置用户分支。迁回主仓前审查准确 diff，不能迁入整个试点工作区。

运行需求：Python 3、macOS/Linux；无第三方 Python 包，界面无 npm 构建。
资料关系与按月维护见 `playbooks/10-资料关联与月度归档.md`；Windows、运行时打包、图谱生命周期和完整历史回填尚未实现。
先用真实任务证明闭环价值，再由下一条产品契约逐项纳入，不宣称完整整合完成。
