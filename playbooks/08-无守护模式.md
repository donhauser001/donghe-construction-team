# 08 · 无人值守模式

适用：用户离开后继续推进已授权目标。时长是预算上限，不是必须消耗的额度。

## 启动

确认用户目标、允许范围、停止条件与回滚点；已有授权不重复问。
有截止时间就遵守；没有时长可以按目标执行，到目标完成即停止。
默认本地隔离分支 / worktree；推送、生产发布按用户已有授权执行。
只列真实可执行任务，不要求凑满固定卡数。未来池中的想法不是授权。

## 每轮决策

1. 有未收口的完工事务 → 优先恢复；冲突保留现场并说明。
2. 有已授权、依赖满足且尚未完成的任务 → 推进一项。
3. 目标完成 / 没有可执行任务 / 剩余均需外部决策 → 停止并交接。
4. 同一阻塞、同一输入且没有新证据 → 不重试；记录唤醒条件。
5. 用户的新消息先响应并纳入任务；只有明确停止或替换目标才取消原目标。

试点项目以 `scripts/donghe.py --project <根> next` 提供本地队列决策。
它不是调度器或权限系统；agent 仍须判断任务授权和外部依赖。

## 验证预算

- 输入、验收命令和环境指纹相同的有效回执直接复用。
- 代码 / 配置 / 验收范围变化、已失败、明确的时效条件或新风险才触发重测。
- 网络、远程部署、浏览器在线状态等不能只凭本地文件判断新鲜度，标记不可复用。
- 已通过的全量测试不作为等待、心跳或任务补给。空队列时不运行测试。
- 一次修复后做相关验证；失败才继续调查，不以反复跑绿代替推进。

## 护栏与交接

保留用户未提交工作。分支成果可以通过独立提交撤销，不使用 reset --hard / force push。
超出授权或触碰不可逆操作时停在边界，能独立推进的其他已授权任务可以继续。
交接只写完成事项、证据路径、剩余问题和唤醒条件；无变化不重复生成日志。
不自动从蓝图造新方向，不以技术债登记替代必要授权。

反例：目标已完成但尚余两小时，于是反复跑测试、自动扩展蓝图、创建无用文档。
正确结果：已有证据可复用，队列清空，记录一次交接并停止。
