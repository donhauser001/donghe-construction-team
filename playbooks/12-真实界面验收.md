# 真实界面验收

有用户界面的任务，先定义用户入口、实际操作、预期反馈和失败路径，再修改代码。验收要分别回答：能力是否接到界面、操作是否可完成、视觉层级/文字/焦点/窄屏是否可理解。后端测试不能替代这些证据。

优先复用宿主浏览器/原生UI和项目现有测试。没有宿主Web工具时，完整包提供标准库CDP适配器与浏览器，`bin/donghe --project <根> ui --spec <契约.json>`；无需用户另装Node或浏览器。

```json
{"authorization":"用户授权隔离界面验收","url":"http://127.0.0.1:4320/","steps":[{"action":"click","selector":"#refresh"},{"action":"assert_visible","selector":"#content"},{"action":"screenshot"}]}
```

同时支持fill和assert_text，字段以`ui --spec`测试用例与脚本契约为准；先跑明确授权的本地隔离页面，不能批量点击用户真实数据。每轮上限60秒/50步，失败留证且非0，清理本轮浏览器。截图只证明画面，不能替代行为断言；浏览器控制并非网络安全沙箱。

产物固定 `docs/东合/证据/UI/<runId>/`。将命令纳入任务验收criteria，动态UI设置reuse:false；失败不能改成screenshot-only通过。保留控制台事实和失败步骤，避免循环到一次绿灯。

移动原生功能需要真实原生环境；本包浏览器不替代iOS/Android设备。病例库本轮已有独立iOS模拟器实测，未宣称实体手机通过。全平台原生自动化不在首版支持矩阵。

受控验收默认只允许入口同源请求；多端口API用契约allowedOrigins显式登记本机origin。适配器追加connect-src CSP（保留原CSP）并停用合成响应环境下的LNA/PNA检查；回执记录这些差异，不能据此认证生产网络安全策略。secret只脱敏契约里的fill值，日志/截图仍需使用合成数据避免出现敏感内容。
