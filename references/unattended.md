# 无守护模式

只在用户说「我走了 / 持续跑 / 你自己跑」时读本文件。

若本文件与用户规则或宿主规则冲突，**宿主 / 用户规则优先**（例如用户规则要求未明确要求则不 commit，就不要自动 commit）。

## 启动前确认

跑多久、范围、commit 策略。默认：在 `auto/YYYY-MM-DD-HHMM` 分支自动 commit，不碰 main / master。

## 铁则

- 不做破坏性 migration / 生产操作 / 删文件 / 引新依赖
- 每完成一件事单独 commit（`[auto]` 前缀），前提是用户规则允许 commit
- 遇到决策点选保守可回滚的方案继续，并留一行记录，不停车等人
- 仅在有实际进展或阻塞变化时更新记录；CLI 项目由 finish 回写，不另写心跳日志
- 目标完成、无可执行的授权任务、时间到或需用户决策时立即停止；时长是上限，不是必须跑满。
- 同一失败无新事实不重试；已通过验证在输入、契约和环境未变时复用。CLI 项目以 next 返回 stop 为停止信号。

## 立刻停

出现下面任一情况，停下写进总结，不要硬闯：

- 撞到密钥、凭证、`.env`、生产库
- 需要 force push / 改保护分支
- 同一验证命令连续失败 3 次
- 用户规则明确禁止的写操作
